## 一、结算逻辑：每个行动是怎么算结果的

行动没有写死的"好结果/坏结果"。点下去后引擎按下图走：

```mermaid
flowchart TD
    A[点击行动] --> B{上板前置 requires<br/>专业/学期窗口/累计次数}
    B -- 不满足且有提示 --> L[🔒 锁定显示<br/>展示解锁路径]
    B -- 满足 --> C[扣行动点]
    C --> D{依序匹配适配分支<br/>第一个 when 命中者生效}
    D -- 技能/数值/时机匹配 --> E[好分支]
    D -- 全不匹配 --> F[默认兜底分支<br/>常是时机错配的教训]
    E --> G{带检定?}
    F --> G
    G -- 是 --> H[掷骰: 成功率=50%+15%×轴值-难度<br/>钳制在5%~95%]
    G -- 否 --> I[直接结算]
    H --> I
    I --> J[数值变化 + 人设标签 +<br/>证书入档 + 可能触发连锁事件]
    J --> K{标签攒到阈值?}
    K -- 是 --> M[✦ 人设觉醒<br/>重编事件卡袋 + 进结局判定]
```

**设计原则**（对应你的要求）：行动本身无好坏，结果只看三件事——**专业是否对口**（majors 过滤）、**时机是否合适**（semesterMin/Max 分支）、**积累是否到位**（能力/数值/累计次数分支）。
