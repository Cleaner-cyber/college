# 05 · 工程架构与开发指南

> v2.0 · 描述当前实现：桌面端游戏结构（Home hub + 关卡页）、Supabase 认证与云存档、引擎如何驱动关卡。
> 契约（类型与 JSON 格式）以 docs/02 为准；后端配置与部署见 docs/07。

## 1. 技术栈与构建

- React 18 + Vite 5 + TypeScript（strict）+ React Router 7（HashRouter）+ Zustand + Tailwind CSS 3
- Supabase JS v2：邮箱+密码认证、Postgres 云存档（RLS）
- 前端产物是纯静态站：`npm run build` 产出 `dist/`，任何静态托管可部署

```
npm install          # 安装
npm run dev          # 本地开发（未配置 .env 时为本地试玩模式）
npm run build        # 类型检查 + 构建（每次改动后必须通过）
npm run preview      # 预览构建产物
```

## 3. 路由与守卫

```
/login        登录/注册（云端模式）；本地模式显示「开始本地试玩」
/onboarding   序章（semester === 'prologue' 时强制进入）
/home         Home 主界面（hub）
/level/:id    主线关卡页（非法 id/已完成/学期不对 → 弹回 /home）
/settlement   结算（主线全完成才可进；y1s1-end 可复看）
```

守卫逻辑（engine/App.tsx 的 `Guard`）：
1. 认证 loading → 加载屏；云端模式未登录 → /login
2. 存档未水合 → 加载屏
3. `semester === 'prologue'` → 强制 /onboarding；反之禁止回序章

HashRouter 是为了纯静态托管零配置；部署在支持 rewrite 的平台可换 BrowserRouter（见 docs/07）。

## 4. 认证与存档数据流

```
App 启动 → auth.init()
  ├─ 无 Supabase 配置 → status='local'  → setSaveAdapter(LocalSaveAdapter)   → engine.hydrate()
  ├─ 有配置：onAuthStateChange
  │    ├─ 登录成功 → status='signed-in' → setSaveAdapter(SupabaseSaveAdapter(userId)) → engine.hydrate()
  │    └─ 登出    → status='signed-out' → setSaveAdapter(null) → engine.unload() → 守卫弹回 /login
```

持久化时机（saveAdapter.ts）：
- `flushState`（立即写）：关卡 onComplete/onEscape、学期流转
- `persistState`（防抖 800ms）：速结行动、序章建档的逐步写入
- 云端表结构见 supabase/schema.sql：`game_saves(user_id pk, state jsonb, semester 生成列, updated_at)`

## 5. 一次关卡的生命周期

```
Home 主线卡片 [进入] → /level/:id
  → LevelPage：registry 查插件 + content.ts 注入 LevelContent
  → 关卡渲染（内部用 ScreenPlayer 驱动 screens）
  → 关卡调用 onComplete(result) / onEscape(result)   ← 关卡唯一出口
  → store.applyLevelResult(levelId, result)
      合并 deltas → 写 archive(补 semester) → 并集 abilities → 记 log
      → 学期流转（prologue→y1s1 发3行动点 / settlement→y1s1-end 剩余点转精力）
      → flushState 落盘
  → navigate('/home')
```

- 主线关卡不耗行动点；速结行动经 `store.runQuickAction`（扣点/入档/记 log）。
- 结算入口条件：`isMainlineComplete(state)`（store 导出的选择器）。

## 5.5 ChatScript：教学关对话的脚本引擎（v2.0 起所有新教学关的标准写法）

`src/components/chat/ChatScript.tsx` 用一个 `ChatStep[]` 数组驱动整段拟真 AI 对话：

| 步骤类型 | 行为 | 文案来源 |
|---|---|---|
| `senpai` | 学长旁白（带头像，自动推进） | copy[key] |
| `npc` | NPC 消息卡（导师/制片人/面试官，自动推进） | copy[key]（名字 npc-name / 来源 npc-msg-app） |
| `chip` | 提示词按钮 → 打字动画 → 发送用户消息 | labelKey / promptKey，可挂 check |
| `chips` | 多选一（面试作答/测验选项），可挂 setVar | options[].labelKey/msgKey |
| `file` | 等待把文件卡拖进对话框（双击为无障碍降级） | nameKey / metaKey |
| `ai` | 思考动画 → 流式 Markdown 回复（可配图、可挂 check） | copy[key] + img 资产 id |
| `button` | 阶段按钮（发给学姐/交付…） | labelKey |

新教学关 = 一份内容 JSON + 一个 ~80 行组件（照抄 `src/levels/notes/index.tsx`，改 STEPS/能力/数值/档案条目；带自定义工作台屏的复杂关参考 `src/levels/coding/index.tsx`）。
**动态个性化**用「包装 api」实现：组件把 `api.copy` 包一层，对特定键返回由 PlayerState 实时生成的文本——简历关（档案 resumeLine 填充初稿）、面试关（按档案挑作品提问、borrowed 追问分支、分岔口方向注入开场）都用这个模式，契约零改动。

交付屏 / [问学长] 逃生口统一用 `src/components/chat/DeliverScreen.tsx`。

## 6. ScreenPlayer：关卡怎么写

`ScreenPlayer` 消化 `LevelContent.screens`，六种 `Screen.type` 有默认渲染。特殊屏通过 `custom` 覆盖：

```tsx
<ScreenPlayer
  content={content}
  globalVars={{ playerName, majorName }}   // 参与 {xxx} 插值
  custom={{ S3: (api) => <MyBench api={api} /> }}
  overlay={(api) => <FloatingBtn />}       // 浮动层（问学长/脚注）
  onFinish={({ vars, checked }) => onComplete(buildResult(...))}
/>
```

`FlowAPI`：`vars / setVar / check / goto / advance / copy(key) / t(text) / nextLabel`。

约定：
- 按钮文案键 `next-{屏id}` / `confirm-{屏id}`，缺省用引擎默认「继续」
- `effects.fakeLoading` 先播；**纯等待屏**（无正文/资产/自定义渲染）加载完自动跳下一屏
- `effects.showAsset` 的资产 id 先插值（如 `poster-{style}-34-v1`）再查 `presetAssets`
- 验收清单：`Choice.checkItem` 自动打钩；自定义屏用 `api.check(id)`；关卡用 `onCheckChange` 镜像给 TaskPanel

## 7. 两个有意为之的引擎服务（不是契约扩展）

1. **建档服务 `ProfileContext`**（engine/profile.ts）：LevelResult 无法承载姓名/专业/flag（契约如此），这些属于"角色创建"。引擎在序章注入 `setName/setMajor/setFlag`，序章经它写入，不触碰 store。
2. **内容查询服务**（engine/content.ts 的 `searchMajors/getMajor/quickActions/boards/ui`）：专业库、行动板配置、引擎级 UI 文案由引擎统一加载；关卡只允许 import 这些**函数**，不允许直接 import JSON。

## 8. 新增一个关卡（checklist）

1. `content/levels/{id}.json`：按 docs/02 §3.1 写 screens/copy/checklist/presetAssets
2. `src/levels/{id}/index.tsx`：导出 `LevelModule`，结束调 `onComplete/onEscape`
3. `engine/content.ts` levelContents 表加 import；`engine/registry.ts` 注册
4. 挂到学期：`content/board/{semester}.json` 的 `mainline` 数组加条目（主线教学关）——或将来扩展选修深度关时按契约提案新格式
5. `npm run build` 通过 + 1280×800 视口走一遍流程

**红线**：关卡不 import store；组件里不写中文字符串；除 Supabase 外不发网络请求；新增契约字段先提案。

## 9. 测试

- 冒烟：Playwright（1280×800）本地模式全流程：序章→Home→主线×2→选修→结算→复看→刷新续玩
