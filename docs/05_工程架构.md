# 05 · 工程架构与开发指南

> v1.0 · 补充文档。描述 demo 的实际实现结构：引擎如何驱动关卡、状态如何流转、如何新增一个关卡。
> 契约（类型与 JSON 格式）以 docs/02 为准，本文不重复。

## 1. 技术栈与构建

- React 18 + Vite 5 + TypeScript（strict）+ Zustand + Tailwind CSS 3
- 纯静态 SPA：`npm run build` 产出 `dist/`，任何静态托管可部署
- 零后端、零 fetch、零运行时 AI 调用；内容 JSON 在**构建期**打包进 bundle

```
npm install     # 安装
npm run dev     # 本地开发
npm run build   # 类型检查 + 构建（每次改动后必须通过）
npm run preview # 预览构建产物
```

## 2. 模块地图

```
src/
  contracts/index.ts      类型契约【冻结，对应 docs/02】
  engine/
    App.tsx               路由/状态机：prologue → y1s1(行动板⇄关卡) → y1s1-end
    store.ts              Zustand 单 store：PlayerState + 引擎动作（关卡不得 import）
    save.ts               localStorage 存档（unisim_save_v1，版本不符清空重开）
    content.ts            内容加载器：构建期 import 全部 /content JSON，提供查询与插值
    ScreenPlayer.tsx       通用逐屏播放器（关卡流程状态机）
    ActionBoard.tsx        行动板（必修置顶/行动列表/速结演出/结算入口）
    registry.ts            关卡注册表 id → LevelModule
    profile.ts             序章建档服务（ProfileContext，见 §5）
  levels/
    prologue/  course-select/  poster/  settlement/
                            每关一个目录，导出 LevelModule
  components/ui/           Button / Typewriter / FakeLoading / HUD / TaskPanel / SpeakerTag
content/                    全部中文文案与配置（levels/ majors/ quick-actions/ board/ ui/）
public/assets/              预设图占位 SVG（文件名 = 资产 id）
```

## 3. 数据流（一次关卡的生命周期）

```
行动板点击行动
  → App.setActiveLevel(id)
  → LevelHost：registry 查插件 + content.ts 注入 LevelContent + 计算行动点成本(含折扣)
  → 关卡渲染（内部用 ScreenPlayer 驱动 screens）
  → 关卡调用 onComplete(result) / onEscape(result)   ← 关卡唯一出口
  → store.applyLevelResult(levelId, cost, result)
      合并 deltas → 写 archive(补 semester) → 并集 abilities
      → 扣行动点 → 记 completedActions → 学期流转 → 写存档
  → 返回行动板
```

学期流转规则（store 内）：`prologue` 完成 → `y1s1` 并发 3 行动点、清空 completedActions；`settlement` 完成 → `y1s1-end`。

速结行动不经过 LevelHost：`ActionBoard → store.runQuickAction(qa)`，同样扣点/入档/存档。

## 4. ScreenPlayer：关卡怎么写

`ScreenPlayer` 消化 `LevelContent.screens`，六种 `Screen.type` 有默认渲染（对话/选择/输入/揭示等）。特殊屏通过 `custom` 覆盖：

```tsx
<ScreenPlayer
  content={content}
  globalVars={{ playerName, majorName }}   // 参与 {xxx} 插值
  custom={{ S3: (api) => <MyBench api={api} /> }}  // 自定义屏
  overlay={(api) => <FloatingBtn />}       // 浮动层（问学长/脚注）
  onFinish={({ vars, checked }) => onComplete(buildResult(...))}
/>
```

`FlowAPI` 提供：`vars / setVar / check / goto / advance / copy(key) / t(text) / nextLabel`。

约定：

- 按钮文案键：`next-{屏id}`（下一步）、`confirm-{屏id}`（输入确认），缺省用引擎默认「继续」。
- `effects.fakeLoading` 由播放器先播；**纯等待屏**（无正文/资产/自定义渲染）加载完自动跳转下一屏。
- `effects.showAsset` 的资产 id 先做变量插值（如 `poster-{style}-34-v1`）再查 `presetAssets`。
- 验收清单：`Choice.checkItem` 自动打钩；自定义屏用 `api.check(id)`；关卡通过 `onCheckChange` 镜像到 TaskPanel。

## 5. 两个有意为之的引擎服务（不是契约扩展）

1. **建档服务 `ProfileContext`**（engine/profile.ts）：LevelResult 无法承载姓名/专业/flag（契约如此），而这些字段属于「角色创建」。引擎在渲染序章时注入 `setName/setMajor/setFlag`，序章经它写入，仍不触碰 store。若未来契约增加 profile 通道，删掉此服务即可。
2. **内容查询服务**（engine/content.ts 的 `searchMajors/getMajor/quickActions/boards/ui`）：专业库、行动板配置、引擎级 UI 文案不属于单关内容，由引擎统一加载；关卡只允许 import 这些**函数**，不允许直接 import JSON。

存档时机比 docs/02 更勤：除 onComplete/onEscape 与学期流转外，速结行动与建档写入也即时落盘（中断续玩粒度更细，不违背契约语义）。

## 6. 新增一个关卡（checklist）

1. `content/levels/{id}.json`：按 docs/02 §3.1 写 screens/copy/checklist/presetAssets。
2. `src/levels/{id}/index.tsx`：导出 `LevelModule`，用 ScreenPlayer + custom 屏实现，结束调 `onComplete/onEscape`。
3. `engine/content.ts`：levelContents 表加一行 import。
4. `engine/registry.ts`：注册模块。
5. 若从行动板进入：`content/board/{semester}.json` 的 `levels` 数组加条目（含耗点与折扣）。
6. `npm run build` 通过 + 手机视口走一遍流程。

**红线**（CLAUDE.md 铁律的落地位置）：关卡不 import store；组件里不写中文字符串；不发任何网络请求；新增字段先提案再动 contracts。
