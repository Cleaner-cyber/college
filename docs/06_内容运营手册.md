# 06 · 内容运营手册

> v1.0 · 补充文档，写给内容负责人：不改代码的前提下，能改什么、怎么改、改完怎么验证。

## 0. 原则

所有玩家看到的中文都在 `/content` 下的 JSON 里。**润色台词 = 改 JSON = 不需要开发介入**；改完跑一次 `npm run build`（或让开发跑）确认 JSON 没写坏即可。

写法约定：

- 台词换行用 `\n`；插值变量 `{playerName}` `{majorName}` `{clubName}` 原样保留。
- 按钮文案键：`next-屏id`（如 `next-S5` 是 S5 屏的下一步按钮）；输入屏确认键 `confirm-屏id`。
- 假加载轮播旁批：`screens[].effects.fakeLoading.tips` 数组，每条 ≤ 18 字最佳；`ms` 是时长（毫秒），可调。

## 2. 专业库（content/majors/majors.json）

- 当前收录 30 个热门专业 + 1 个兜底 `generic`（**不要删**，搜索无结果时自动使用）。
- 新增专业：复制一个条目改内容。`id` 用小写英文短横线；`aliases` 放考生常搜的简称（如「计科」「CS」）。
- 卡片五栏字数建议：主干课 ≤6 门；毕业去向 ≤4 条；`secret`（没人告诉你的一件事）是传播点，一句话、有信息差、不贩卖焦虑。

## 3. 替换海报真图

> 现状：`public/assets/` 下所有资产已从灰盒占位升级为**成品级扁平插画/文档版式**（统一米白·墨色·赤陶橙基调），可直接上线。下表的"同名替换"机制依然有效——将来要换成实拍照片/真实设计稿，同名覆盖即可，不改代码。

1. 真图按下表命名，直接放进 `public/assets/` 覆盖同名文件。改扩展名（如 .svg → .jpg）时同步改对应关卡 JSON `presetAssets` 里的路径即可；文件夹作品卡支持带扩展名的 `assetRef`（海报关已是 .jpg 真图）。
2. 尺寸参考：竖版海报 3:4（750×1000 起），场景 1600×900，立绘 480×760。

| 文件名 | 内容要求 |
|---|---|
| `poster-acg-v1.jpg` | 海报关首版（深色动漫风，真实 AI 生图）——学姐夸完整但要改风格 |
| `poster-acg-v2.jpg` | 第二版（清新校园插画风 + logo，真实 AI 生图），二维码区仍是虚线框 |
| `poster-acg-final.jpg` | 终稿（剪映合成真二维码后），入玩家作品集 |
| `club-logo.webp` | 星野动漫社 logo（关内拖拽的"参考图"文件卡） |
| `poster-senpai-34` | 学长成品海报（走[问学长]时展示与入库） |
| `senpai.svg` | **学长头像**（扁平插画占位）。换成真素材时同名替换，全站自动更新 |
| `sprite-senpai` / `sprite-xuejie` | **角色立绘**（VN 演出用，480×760 半身）。同名替换即可；新增角色则在关卡 JSON 的 presetAssets 登记 |
| `bg-desk / bg-gate / bg-classroom / bg-club / bg-dorm / bg-office / bg-lab / bg-studio / bg-meeting` | **场景背景**（1600×900）。哪个屏用哪张背景在关卡 JSON `copy` 的 `scene-屏id` 配置，纯改 JSON 即可换场景 |
| `sprite-prof`（导师）/ `sprite-hr`（制片人·面试官） | 大二起登场的 NPC 立绘，同名替换 |
| `notes-doc / dachuang-chart / gig-board-v1 / gig-board-v2 / resume-doc / thesis-doc / ppt-deck-*` | 各关交付物占位图，同名替换真图 |
| `icon-trae / icon-cursor / icon-claude-code` | 编程关工具推荐卡图标（96×96）。拿到官方 logo 素材后同名替换 |
| `homepage-doc` | 个人网站在文件夹·作品集里的缩略图（600×400），同名替换真截图 |

注意：海报三张真图（v1/v2/final）是一套连贯剧情素材（深色动漫 → 清新校园 → 合成二维码），替换时三张要一起换、剧情逻辑保持一致；`poster-acg-v2` 左下必须保留"二维码放置区"虚线框（AI 画码翻车的黑马赛克演出叠加在该区域）。

## 4. 改完后的验收清单（对照 docs/01 Demo 验收标准）

- [ ] `npm run build` 零报错（JSON 语法坏了这里会挂）
- [ ] 桌面端（1280px）走完整流程 ≤ 15 分钟：注册/登录 → 序章 → 主线×2 → 速结 → 结算
- [ ] 主线必修绕不过：不做完选课+海报，「结束这学期」不可点
- [ ] 序章选一个小众词（如「敦煌学」）→ 出兜底通用卡，文案不尴尬
- [ ] 海报关走一次 [问学长] → 文件夹出现「借来的」标签，结局卡「自己做了 N/M 件」数字变化
- [ ] 中途关掉浏览器再打开（或换设备登录同一账号）→ 从 Home 继续
- [ ] 全程除 Supabase 外无网络请求（开发者工具 Network 检查）

## 5. 文案基调备忘（从 docs/01/03 提炼）

- 学长：过来人，不端着，不客服腔；可以自嘲（「我当年没读」），不说教。
- 差结局/低产出不羞辱：「什么都不做」的判词也要体面（见 `verdict-rest`）。
- flag 屏基调：认真但不施压，脚注「随便选。反正你会忘。」是定调句，慎改。
- 教学口诀是资产，改前过一遍负责人：「别读长文件，喂长文件」「尺寸是参数，构图才需要你说话」「改提示词，不是重新许愿」。
