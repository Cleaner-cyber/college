## 工程 B · 部署到 Zeabur ✅ 已上线

**2026-08-12 上线：https://college.zeabur.app**（腾讯新加坡节点，云端模式已验证——
线上 bundle 与本地 E2E 验证版本哈希一致）。收尾项：Supabase Site URL 回填线上域名。

纯静态站（`npm run build` → dist/，HashRouter 无需服务端路由回退），Zeabur 是最简部署形态。

- 仓库根已加 `zbpack.json`（build 命令 + 产物目录），Zeabur 识别为静态站点零配置部署
- 步骤（用户 5 分钟）：zeabur.com 注册 → New Project → Deploy from GitHub → 选本仓库
  （分支选 main 或当前开发分支）→ Environment Variables 里填 `VITE_SUPABASE_URL` 和
  `VITE_SUPABASE_ANON_KEY` → Deploy → Networking 里生成域名（xxx.zeabur.app）
- anon key 是公开密钥（RLS 兜底安全），进前端构建产物是设计内行为
- Supabase 侧要配：Authentication → URL Configuration → Site URL 填 Zeabur 域名
  （否则重置邮件的回跳链接是 localhost）
- 自定义域名可后配；**若走小程序 webview 路线则必须绑已备案域名**（见工程 C）

## 工程 C · 微信小程序（分三期，先给结论）

**结论：不重写。先做 H5 移动端适配（一期），再套小程序 webview 壳（二期）；
Taro/uni-app 原生重写（三期）仅当 webview 路线被政策卡死才启动。**

理由：本项目重度依赖 DOM（拖拽、hover 浮层、SVG 树、backdrop-filter），原生小程序无 DOM，
重写等于换引擎重做一遍；webview 路线能复用 100% 现有代码。

### 一期 · H5 移动端适配（纯前端，我可直接开工）

现状是桌面优先（1280 基准 / 1024 不破版），移动端要动的面：

1. **布局**：三个单屏面板在窄屏改纵向流（移动端允许纵滚，单屏铁则只约束桌面）；
   关卡页双栏（需求单+聊天窗）改上下叠；VN 立绘/对话盒比例重排
2. **交互替换**：hover 浮层（词条/技能树/行动瓦片详情）→ 点按展开；
   拖拽喂文件 → 已有双击路径直接复用为「点按上传」
3. **触控热区**：按钮/chip 最小 44px；顶栏 HUD 折叠为可展开的摘要条
4. 视口断点：`md`（768）为分界，桌面样式全部不动

### 二期 · 小程序 webview 壳

- 新建小程序工程：一个页面 + `<web-view src="https://已备案域名/">`
- **硬性前置**：web-view 的业务域名必须是**已 ICP 备案**的域名（zeabur.app 默认域名不行），
  且要在小程序后台配置业务域名并放校验文件——这是本路线唯一的坎
- 登录：webview 里继续用邮箱密码（微信登录一键授权留到三期评估）

### 三期（暂缓）· Taro 原生重写

只在 webview 审核不过/体验不达标时评估；届时引擎层（store/contracts/content）可整包复用，
重写的只有渲染层。
